# Написать issue

Инструмент — MCP `user-GitKraken`, `issues_create` и `issues_get_detail`. Перед первым вызовом — `GetDynamicTools`. Репозиторий — `docs/agents/issue-tracker.md`.

## Тело

Как у формы `.github/ISSUE_TEMPLATE/change.yml`:

- Область: одна или несколько из session, dossier, model, access, docs.
- Кто сталкивается — не заполнять, если роль ни при чём, например для docs.
- Что сейчас.
- Что должно быть.
- Критерии приёмки: 2–5 пунктов «Дано / Когда / Тогда». Хотя бы один негативный.
- Для реализации: файлы и что не менять.

Для поведения тренажёра каждый критерий потом станет тестом в `test/`. Для docs в теле прямо написать, чем проверять.

## Перед созданием

1. Критерий можно проверить. Два прочтения — сначала вопрос человеку.
2. Негативный критерий есть.
3. Область выбрана.
4. Дубля нет: открытые issue с тем же смыслом не создавать второй раз. Список `issues_assigned_to_me` с `assigned_to_me=false` неполный для закрытых номеров; сверять ещё `issues_get_detail` по номерам, которые уже звучали.

Очередь из плана — отдельные issue по зависимости. Код и правку только правил не смешивать, если план их развёл.

## После ошибки создания

`issues_create` иногда отвечает ошибкой, хотя объект уже есть.

1. Перед вызовом запомнить наибольший номер. Нумерация issue и pull request общая.
2. После ошибки — `issues_get_detail` по номерам выше него, пока не найдётся объект с тем же заголовком или не вернётся «не найдено».
3. Нашли — создание не повторять. Не нашли — один повтор.
